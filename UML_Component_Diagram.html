#PatternCategoryComponentProblem Solved
1 Singleton Creational SubmissionStore Guarantees exactly one in-memory submission list shared by all engine components
2 Builder Creational ReceiptBuilder Constructs complex 7-field receipt objects step-by-step; resets after every build
3 Factory Method Creational ReceiptFactory Creates the correct receipt type (OnTime / Late / Rejected) without the caller knowing which
4 Template Method Behavioral BaseValidator → HashFormatValidator, DeadlineValidator Defines the validation skeleton (pre → do → post); subclasses override only the specific algorithm step
5 Observer Behavioral EventBus SubmissionAPI publishes events; audit logger and counter observe without being known to the publisher
6 Facade Structural SubmissionAPI (engine) · SubmissionClient (browser) Hides the 7-class engine pipeline behind one submit() call; HTTP handler stays at 3 lines per route
7 Strategy Behavioral HashValidationStrategy (portal) · FilterStrategy (gradebook) Pluggable validation and filter algorithms — same pattern applied in two different subsystems
